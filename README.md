# 内部工具库网页

> 把散在各人电脑里的自建小工具收成**一张网页**：员工自己打开、自己找、自己下、自己看说明，不用每次找开发者要包。

PDF 比对、PDF 拼接、一致性检查这些工具一直在做，但分发方式是「微信传一个 zip」或者 U 盘拷。同一个人手里常常同时躺着 4.0 和 5.0 两个包，分不清哪个最新；说明书和包分开传，时间一长就找不到了。
每发一版都要重新传一遍，人一多就是重复劳动；旧版本在别人电脑上长期不删，反馈上来先得问「你用的哪一版」。

现在开发者只把包丢进 `软件工具库/`，点一下「刷新清单」；员工打开一个网址就看到全部工具、当前版本、更新日期和说明。**打开网页从 19.8 秒降到 0.65 秒。**

## 这个仓库里没有 runtime

完整发布包自带 Python 运行时（`runtime/`，37.8 MB，Windows x64），空电脑双击就能用。运行环境属于二进制资产，不进版本库。

**本仓库是纯代码 + 文档**：`admin/` 里的两个脚本、页面本体、维护手册，加两个启动器。
要真正跑起来，把本目录放进完整发布包（或在同目录补一个 `runtime/`），然后双击启动器。

## 结构

```
.
├── 启动工具库.bat            # Windows 入口（双击）
├── 启动工具库.command        # macOS 入口（双击）
└── admin/
    ├── serve.py              # 本机小服务：只监听 127.0.0.1
    ├── build_index.py        # 扫两个柜子，生成清单
    ├── 软件库网站.html        # 页面本体（由 build_index.py 生成）
    ├── config.json           # 标题 / 联系人 / 两个柜子的目录名
    ├── 更新索引.bat           # 手动重建清单
    └── 维护手册.md            # 日常四种操作：加工具、换版本、改信息、排错
```

`软件工具库/` 与 `文档代码库/` 是数据目录（随包装，不进仓库）。

## 架构：页面 + 本机小服务两条腿

页面只管长相和数据；`serve.py` 只监听 `127.0.0.1`，负责**扫盘、把 zip 复制进剪贴板、打开资源管理器** —— 这三件事浏览器的沙箱做不到，只能由本机进程代劳。

**包信息不靠人工登记**：只读 zip 末尾的中央目录（EOCD + `0x02014b50`），拿包根目录的文件名与文件夹名，**不解压**，二十几 MB 的包也只读末尾几 KB。
校验码按「路径 + 大小 + 修改时间」缓存进 `索引缓存.json`，大包不再每次重算。

**两个柜子**：

| 柜子 | 放什么 | 版本 |
|---|---|---|
| `软件工具库/` | 能下载装到本机的离线工具 | 留历史版本：同一工具多个 zip 时版本号最高的当当前版，其余自动进「历史 N」 |
| `文档代码库/` | skill / 代码 / 规范，不用安装直接看 | 不写版本号、不产生历史版本，一个文件夹就是当前这份 |

两柜按钮一致：**复制**（把 zip 本身放进剪贴板，粘到文件夹就是原件，不带「来自 Internet」标记）→ **下载** → **说明**。
下载全走相对路径，整个文件夹搬到哪都能用；卡片右下角写清「找谁」。

**三层降级**：`runtime/python.exe`（随包自带，空电脑也能跑）→ 系统已装的 Python → 都没有就直接开网页（浏览器授权读盘，能看能下载，复制降级成复制文件路径）。

**启动不等扫描**：先把服务起起来、浏览器打开，扫描丢后台，页面先用手上这份清单渲染，扫完自己补上。

## 跨平台

两个启动器同名不同后缀：

- `启动工具库.bat` —— Windows，优先 `runtime\python.exe`
- `启动工具库.command` —— macOS，查找顺序 `runtime/bin/python3` → Homebrew（arm64 / Intel）→ python.org 框架版 → 系统 `/usr/bin/python3` → `PATH` → 都没有就只开网页

macOS 下**不先开 `file://` 页面**，而是让 `serve.py` 自己把浏览器开在 `http://127.0.0.1:端口/` 上：
Safari 对 `file://` 页面去 `fetch` 本地服务有额外限制，页面可能探不到服务，就一直是「离线清单」、按钮全部降级；从 http 打开时页面与服务同源，「打开文件夹 / 复制」直接就通。

端口在 **8765~8785** 之间靠 bind 试探占用，全被占满直接报错退出。

## 已知限制

1. 「复制到剪贴板」「打开文件夹」依赖本机小服务。纯网页模式（既没有 runtime 也没装 Python）下用不了，会降级成复制文件路径。
2. 本机服务只监听 `127.0.0.1`、不对外，但**没有账号与权限体系**：能改这个文件夹的人都能改数据，只能靠共享盘权限管。
3. 文档代码库不产生历史版本，旧的同名文件夹要人工删。
4. 版本号、姓名全靠文件夹名识别，命名不规范会认错（认不出来会提示一句，不会静默处理）。

## 快速开始

```bash
# Windows
启动工具库.bat

# macOS
./启动工具库.command
```

然后浏览器打开 `http://127.0.0.1:8765/`（端口以 `admin/运行端口.txt` 为准）。
手动重建清单：`python3 admin/build_index.py`。
日常维护看 `admin/维护手册.md`。
